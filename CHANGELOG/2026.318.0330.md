# 2026.318.0330 — refactor(k8sgen): read the cluster body through the plugin's own view

## Summary

`opencharly/spec#304` unit 5, a consumer leg. The authored `#Kubernetes` body — and the Go type generated from it — moves into the plugin that **serves** the kind (`opencharly/plugin-substrate#35`, merged), so this plugin can no longer borrow `spec.Kubernetes` to read the cluster policy it generates against.

**The wire was already built for this.** The kernel ships the body OPAQUELY (`#KubernetesGenInput.cluster_raw`, "Cutover K"), and the contract's own note names this plugin as the decoder: *"the full cluster model rides opaquely in `Raw` and is decoded by `candy/plugin-k8sgen`, never the kernel."* So this leg writes the decoder:

- **`clusterspec.go`** (new): the plugin's own view of the cluster — exactly the **fields the generator reads**, with the authored JSON tags (`storage`, `ingress`, `image_default`, `pod_default`, `defaults`, `default_namespace`, `admission_policy`), plus `genInput`, which embeds the contract's request wire and carries the view.
- **`main.go`**: decodes `cluster_raw` into the view instead of into the authored type.
- **`k8sgen.go`**: the generator's 16 signatures and field reads move to the view.
- **The fixtures** seed the wire the kernel actually sends (`{"box":"app","default_namespace":"myns"}`) instead of the authored type, so the tests exercise the real path.

No contract type is left in this plugin's path; the ONE remaining mention is the comment in `clusterspec.go` that explains why.
